# 需求确认单与 MVP 边界

## 1. 项目一句话定义

把分散在各地招投标网站的公告，通过「自动采集 → 结构化入库 → 订阅匹配 → 飞书群推送」的链路，
及时送到客户手上；并提供一个内部后台，用于查看公告与追踪推送结果、管理订阅条件。

## 2. 用户与场景

| 角色 | 场景 | 诉求 |
| --- | --- | --- |
| 内部运营 | 查看今日采集到的公告 | 按关键词/地区/类型/时间快速筛选，点开看详情与原文 |
| 内部运营 | 排查某条客户投诉"没收到公告" | 从推送记录查到该订阅的发送状态与失败原因 |
| 内部运营 | 排查采集异常 | 从抓取日志看每轮的成功/失败/转人工条数与源站 |
| 内部运营 | 客户新增/变更订阅条件 | 在订阅管理页新建、编辑、停用订阅 |

## 3. 功能需求

### 3.1 公告列表（P0）

- 分页查询公告，支持 关键词 / 地区 / 公告类型 / 发布时间范围 / 来源站点 筛选
- 列表列：公告标题、类型、采购人、地区、预算（万元）、发布时间、操作
- 点击标题或「查看详情」进入公告详情
- 标题行展示「今日新增 N 条」

### 3.2 公告详情（P0）

- 基本信息：采购人、预算金额、投标截止时间（含剩余天数）、代理机构、联系人、联系电话
- Meta：来源站点、发布时间、公告编号
- 正文摘要（取自 `bid_detail.structured`）
- 「查看原文」跳转 `detail_url`
- 结构化字段缺失时显示「—」，**不报错**

### 3.3 订阅管理（P0）

- 列表：订阅名称、关键词、地区、公告类型、推送渠道、启用状态（开关）、操作
- 新建 / 编辑订阅（弹窗表单，Zod 校验）
- 启用 / 停用切换
- 标题行展示「已启用 N / 共 M 条订阅」
- 关键词支持 `/` 分隔的多关键词；地区/类型为空表示不限

### 3.4 推送记录（P0）

- 统计卡：今日推送次数、推送成功、推送失败
- 明细：推送时间、接收订阅、匹配公告、渠道、状态、失败原因
- 成功记录失败原因列显示「—」，失败记录显示错误原因（红色）
- 点击匹配公告可跳转公告详情

### 3.5 抓取日志（P1）

- 按执行轮次查看：执行时间、源站（含 A/B/C 级标签）、抓取总数、成功、失败、人工处理、备注
- **纯只读**，无手动触发入口
- 标题行展示「今日执行 N 轮，累计抓取 M 条」

## 4. MVP 边界

### 4.1 做

- ✅ 5 个业务页面（见 §3）
- ✅ 公告、详情、日志的**只读**查询
- ✅ 订阅的增 / 改 / 启用停用
- ✅ 统一的接口信封与分页结构
- ✅ 空数据态、加载态、错误态

### 4.2 不做（本期明确排除）

| 不做 | 原因 |
| --- | --- |
| ❌ 登录鉴权 | MVP 内部使用，原型无登录页；顶栏用户「陈钢」静态展示 |
| ❌ 源站（站点）管理 | 源站配置只在飞书多维表格，Supabase 不镜像 |
| ❌ 「立即抓取」按钮 | 违反"应用不抓外部网站"红线，抓取入口只在 n8n |
| ❌ 「立即推送 / 重新推送」按钮 | 推送是 n8n 入库后的自动子流程 |
| ❌ 抓取状态编辑 | 状态由 n8n 与人工决定，禁止自动把「待人工」改成「已入库」 |
| ❌ 多租户 / 角色权限 | 无需求 |
| ❌ 数据导出、图表大盘 | 无需求 |
| ❌ 邮件 / Webhook 渠道的实际发送 | 首期只发飞书群机器人，渠道字段预留 |

## 5. 开发阶段确认的边界问题（2026-09-17）

| # | 问题 | 结论 |
| --- | --- | --- |
| Q1 | 系统设计写"四个业务页面"，但原型有 5 页（多了抓取日志） | **按原型做 5 页**，新增 `GET /api/crawl-logs`，侧栏 4 个菜单项 |
| Q2 | 原型有字段但建表脚本没有（订阅名称、抓取日志源站/等级、公告编号、发布时间精度） | **补字段并生成增量迁移**：`bid_subscription.name`、`bid_crawl_log.source_site`/`site_level`、`bid_announce.announce_no`，`publish_date` 改 `TIMESTAMPTZ` |
| Q3 | 原型有「立即抓取」按钮，与"应用不抓外网"红线冲突 | **不做该按钮**，抓取日志页纯只读 |
| Q4 | Supabase 环境 | 项目已存在，用户提供 Project URL + key 后本地联调（**凭据待提供**） |

## 6. 非功能需求

| 项 | 要求 |
| --- | --- |
| 分辨率 | 桌面优先，1440 基准；<1200px 侧栏收窄至 200px，表格横向滚动 |
| 数据量 | MVP 千级公告；分页每页 20 条 |
| 性能 | 过滤、排序、分页全部在数据库层完成，禁止拉全表到应用层 |
| 稳定性 | `structured` 解析失败降级展示，绝不白屏 |
| 安全 | `service_role` 只存在于服务端；`bid_subscription` 不向 anon 开放 |

## 7. 验收标准

- [ ] 能从一条列表公告 → 详情入库 → 页面展示 → 订阅匹配 → 推送记录，全链路可追踪
- [ ] 5 个页面均可访问，无运行时报错
- [ ] 7 个接口均返回统一信封 `{ code, message, data, traceId }`
- [ ] 空数据、接口异常时页面有明确提示，不白屏
- [ ] `npm run typecheck` 与 `npm run build` 均通过
- [ ] 浏览器端网络请求中不含 `service_role` 凭据
